## Notes & decisions in flight

- AOF drives board updates. The local milestone folder survives publication and stays in place
  while the milestone is in flight. External edits stop the workflow. The recovery direction
  is an explicit resync from AOF to the board.
- Archiving applies only in local file mode. Board-backed milestones keep their document home and board link through completion and any pending final update (209/02 Q2).
- Only a change by someone else to a tracked field stops the workflow: title, state, parent, dependencies or order. Comments, tags, unmapped fields and attachments do not (209/03 Q1).
- A conflict halts every workflow whose scope contains the item, meaning loops and lanes under the same top-level ref. Workflows on other milestones and board writes to other items continue (209/03 Q2).
- Resync never recreates an item deleted on the board. It stays stopped until the operator restores the item from the recycle bin (209/03 Q3).
- `board-conflict` joins the loop's operator stops, so no repair session can clear it. Story 03 updates the five suites that pin the stop list.
- The live Azure run uses a new test project on the AOF inherited process in the umair-butt organization. Umairs Homebase is left untouched (209/05 Q1).
- Story 04 adds a read-only `aof work board-access` verb, which the preflight runs in the daemon's environment. Stories 03 and 04 both register a verb, so their write sets overlap and they build one after the other.
- Completing refinement triggers the first publication of a local draft to the selected board (209/02 Q1).
