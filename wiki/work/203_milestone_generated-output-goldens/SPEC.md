# 203 · Every file aof generates is held to a committed baseline, and any drift shows as a reviewable diff

## Objective

aof's product is the files it writes into a project: commands, agents, skills, templates, loops,
triggers, the frozen set, hooks and runtime settings, for Claude Code, Codex and opencode. Today
nothing shows what a change does to those files.

- `packages/core/assets/manifest.json` holds a hash for each of 187 rendered files, for one
  configuration. Its fitness function (`acd-bundle-manifest-hashes`) says that something changed,
  not what.
- Practices and integrations that are switched on, and opencode, are not covered at all.
- Most prose tests check tokens by hand, so a refactor that moves a sentence passes while one that
  drops a slot's fill may not be caught.

This milestone gives aof the equivalent of screenshot regression for its generated output. A real
generating verb runs in a temp project and a temp global home, and the whole tree it leaves is
compared with a committed baseline. Drift fails with a unified diff per file. A change that is
meant is accepted by rewriting the baseline with an explicit flag, and the new baseline is reviewed
in the PR like any other diff.

This is the safety net for the refactors and integrations that follow, starting with moving ACD
into its own package: their acceptance is "the diff is empty".

It is met when an intentional prose edit shows exactly that edit as a diff, an unchanged tree diffs
empty in every scenario, and the suite runs isolated under `AOF_GLOBAL_HOME`, with a Windows-shaped
capture of every scenario normalising to the same baselines on any OS (amended at verify, 2026-11-21:
was "on macOS and Windows", a run on each).

## Scope

In scope:
- **The harness.** It runs a verb black-box in a temp project with a temp global home, captures
  both trees, compares them with a committed baseline and prints:
  - a summary of files added, removed and changed;
  - a unified diff for each changed file.
- **The update flow.** An explicit flag rewrites the baselines. A plain run never writes one.
- **Normalisation.** Version, build id, content hashes, timestamps, absolute paths, line endings
  and path separators are normalised, so one baseline holds on macOS, Windows and Linux.
- **Deterministic output.** Wherever the render is not stable run to run (ordering, timestamps),
  it is fixed at the source, not hidden by the normaliser.
- **The first lane: `aof work init` and `aof work update`**, over named scenarios:
  - profiles `default`, `all-practices` (discovery, operator-aware, build brief, learning),
    `notion` and `hyperagent`;
  - runtimes Claude Code, Codex and opencode;
  - starting states: an empty folder, and a project with user customisations beside aof's files.
- **Idempotence.** `update` run on a baseline's own output changes nothing.
- **Upgrade.** A tree generated by the previous baseline, run through `update`, produces exactly
  the expected changes.

Out of scope:
- `aof apply`, `aof init` and `aof clean`. These are covered by 204, on this
  harness.
- `aof work` verbs over a work stream. These are covered by 205.
- How agents behave when run. Model output varies between runs, so it cannot be held to a diff.
- Retiring `manifest.json` or its fitness function. The installer still uses its hashes to spot
  drift. Revisit once this suite has bedded in.
