# 158 · Build brief

## Mechanism

Enable the admitted Codex native automatic reviewer at the existing thread
start/resume boundary and check its effective response before starting a turn.
Keep the selected sandbox/model/effort unchanged. The native reviewer owns actual
permissions; AOF retains the no-grant handler for unexpected client approval RPCs.
Carry the operator's work scope in the existing phase brief without adding a new
approval command, durable answer transport or decision-making model.

Extend the existing native event normalization and run observation reduction for
bounded review metadata. Keep review identity distinct from target item identity,
and pending reviews distinct from completed tool work. Existing runtime callbacks,
heartbeat and drive cancellation are the integration seams. Confirm worker and
graph entry points reach this same behavior, including resumed native sessions.

## Verification

Start with both admitted protocol fixtures, then exercise the real drive/run-store
and worker bindings with scripted transport. Prove positive continuation and denied,
timed-out, disconnected, malformed and persistence-fault behavior. Exercise concurrent
reviews and reused native ids across runs. Run the resolved impacted test scope,
registered controls and their red probes; keep dependency installation unnecessary.

Then observe real Windows Astra/high verification after a completed build and old
permission failure. Establish the blocked subprocess, native automatic review,
operation result and subsequent verification in the same native context. Record
which tests actually ran and retain old run history. Approval alone is not proof.

## Out of scope

New approval UI, Discord decisions, blanket permission bypass, persistent allow rules,
another AOF reviewer, automatic override of native denial, new provider support,
dependency updates, and edits to delivered acceptance contracts.
