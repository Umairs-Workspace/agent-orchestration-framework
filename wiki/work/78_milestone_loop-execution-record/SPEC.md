# 78 · The loop execution record — a committed graph of what actually ran, that a human signs

## Objective

aof declares its loops and renders them. It cannot show you the ones that **ran**.

`aof work loops graph` emits a deterministic Mermaid flowchart of the registry
(`src/commands/loops-graph.mjs:41-73`) — to **stdout only**. There is no `--out`, no path input, and
writing is not merely absent but forbidden: milestone 52 gates itself on containing no code path that
writes under the registry directory (FF-5201). Its own ADR-009 anticipated the gap and left it open:

> *"The rendering is **committable — a `loops.mmd` in a PR is a reviewable artifact** — which is the
> PRD's governance test met literally."* (`52/ARCHITECTURE.md:876-878`)

That is a shell redirect, not a deliverable, and it renders the same nine framework-wide nodes
whatever item you are looking at. It is also, deliberately, the whole of 52's ambition: *"A future
milestone can add a face additively with no change here"* (`52/ARCHITECTURE.md:869-870`). **This is
that milestone.**

**The blocker, stated plainly: "the loop graph for a work item" is not expressible today, because
nothing that executes names a loop.** No run record, no effects-journal entry and no observability
row carries a `loop:<id>`. The registry describes the framework and is *"identical in every repo that
installs aof"* (`53/07/STORY.md:53-56`); the item `depends` DAG and the graphify code graph are two
other graphs entirely (`52/SPEC.md:69-70`). Rendering "the graph for item 54" would either repeat the
global picture per item — worthless — or project something nothing currently computes.

**Milestone 53 supplies the missing join.** Its loop declaration is the seven-key envelope
`{loopRunId, scope, level, cap, phase, cycle, startedAt}` riding the `brief` bag of every run the
loop mints (`53/01/tasks/05_declaration-and-resume.feature:8-11, :31-33`), and 53 already argues that
this makes a loop's history *"a one-key filter over runs rather than a document some second store
would have to keep in step"* (`53/02/tasks/06_loop-state-on-the-board.feature:20-21`).

That argument is right about the **store** and incomplete about the **reader**. A one-key filter over
JSON run records is a query, not something an operator can look at, and nothing in 52–63 turns it
into one. Today's run records prove the point: all ten on disk carry `sessionId: null` and
`brief: {}` — the two fields that would bridge a run to anything are unwritten.

So this milestone builds the reader, and one thing 53 does not claim: **a place for a human to say
the execution was acceptable.** The arc has no machine-readable sign-off of any kind. `@uat` tags on
scenarios plus prose in `## Accept decision` are the entire vocabulary, and milestone 54 —
the obvious-looking home for this work — explicitly declines to touch it: *"**Human acceptance
(`@uat`)** — unchanged; a genuine human gate still pauses and surfaces"* (`54/SPEC.md:60`). 54 also
`depends: [53]` and not 52, and never mentions the registry, the graph, an edge, a node or a
rendering. It is the grader-loop milestone. This is not its job.

**Why it is worth a document rather than a dashboard.** aof's own evidence says a generated report
nobody is obliged to read changes nothing: `aof work observe` has written
`<item>/observability/report.md` since milestone 45, and its header disclaims itself — *"a
diagnostic, not a work record — safe to delete or `.gitignore`"* — so only 2 of ~20 items have one,
and the framework's most recent milestone shipped with none at all. A record that is committed,
reviewed in the PR, and signed is a different object from a report that is generated and ignored.

## Scope

In scope:
- **A per-item loop execution record, written to disk, committed with the work.** One markdown
  document under the work item, generated by a registered command, carrying:
  - **The graph, scoped to what ran** — the loops actually engaged for this item, their actuators
    and their reference owners, rendered as Mermaid so it displays wherever markdown displays.
  - **The execution facts against the declaration** — per loop: cycles observed against the declared
    `ceiling`, phases entered, attempts and the retry chain, terminal outcome, stop reason. A
    `ceiling: uncapped` loop and a capped one must not produce identical records; today they do.
  - **The gaps, named** — a loop that ran and is not declared, a declared loop that never ran, an
    authority that could not be resolved. Absence is the finding, stated rather than omitted.
- **A frozen sign-off section with a shape a check can read.** Following milestone 66's law: a frozen
  `h2`, a frozen table header, the id alone in the first cell. A signature that is prose in a
  paragraph is not checkable and will drift.
- **The record is a face, never a second truth.** It is derived from a registered `work:*` command
  with a stable `--json` contract, per the milestone-08 spine and
  `PRD-acd-loop-engineering.md:112-114`. Regenerating it on unchanged inputs is byte-identical;
  the human signature is the one part not derivable and therefore the one part preserved across a
  regeneration.
- ~~**`work:loops-*` becomes board-reachable.** The three loop commands are registered but absent from
  the frozen `WORK_IDS` and served by no `/api/work` route — an inherited red already recorded as
  chore 64 and finding F-73-Q. A record nobody can reach from the board is half a deliverable.~~
  **WITHDRAWN at refine, 2026-09-03 — see `ARCHITECTURE.md` ADR-008.** Chore 64 is `done` and closed
  this gap in the OPPOSITE direction: all four loop commands are now `BOARD_DEFERRED` members
  (`test/arch/acd-work-command-route-coverage.test.mjs:143-160`) and present in `WORK_IDS`
  (`test/command-core-contract.test.mjs:116-119`), with the reasoning recorded in place — *"a board
  face for this family is not a deferral awaiting a decision — it is a decision already recorded at
  53's gate"*, because 52/FF-5202 asserts `ui/` never references the loop family. `work:loop-record`
  joins the same carve-out. The surface stays the one this SPEC already names: a markdown file the
  operator has in their editor.

Out of scope:
- **Instrumenting the loops.** The join key is `brief.loop` and it belongs to **53**. This milestone
  reads it; if 53 has not populated it, this milestone renders the absence honestly and says so.
- **Making the record gate acceptance.** Deliberately deferred, and see the open question below —
  milestone 66 faced the same decision about the observability report and *"deliberately left alone:
  the measure→decide path already works through a human"* (`66/SPEC.md:80-81`). Whether an unsigned
  record should block `aof work status <ref> done` is a real question with a real argument on both
  sides, and it is decided at refine, not assumed here.
- **Extending `renderLoopGraph`.** Its bytes are frozen by FF-5208 across ten structural-duplicate
  scenarios. This milestone writes a new renderer that reuses the conventions — `flowchart LR`,
  code-unit sort, collision-safe node keys, the three glyphs — and does not touch the frozen one.
- **Writing anything under the registry directory.** FF-5201 forbids it, and 53/07 is moving the
  registry to `.aof/loops/` anyway. The record lands under the work item.
- **Fixing the registry's honesty.** The day-one registry validates with **0 errors and 40
  warnings** and cannot fail: 12 of 21 authority slots are `prose:` only, nothing checks that a cited
  path exists or a symbol resolves, and the graph carries **2 edges across 9 nodes** — no
  `monitoring`, no `veto`, no `parameter-tuning`, no `data-feed`. That is 55's and 57's work. This
  milestone renders what is there and names what is not.
- **The declared graph as a committed document** — that is story **79**, which needs nothing from 53
  and should land first. This milestone is the *executed* graph.
- **A web/UI panel.** 52 rejected one and left the door open additively; the same reasoning holds. A
  markdown file the operator already has in their editor is the surface.

## Stories

Broken down 2026-09-03 (`aof:refine 78`). Boundaries drawn from `aof graph impact` over a graph built
at refine — the two pure leaves import nothing shared and can be built in parallel; the two edge
stories each touch a different shared file. See `ARCHITECTURE.md` §Story boundaries.

- [x] `00_story_execution-projection` — the execution model: what ran, against what was declared.
      Pure; takes injected records, returns a model.
- [x] `01_story_item-scoped-renderer` — the graph of what ran plus the document body, in bytes a diff
      can hold still. Pure; imports 52's frozen glyph table rather than restating it.
- [x] `02_story_the-record-command` — `work:loop-record`: a read face, `--write` as the only door to
      disk, and a signature that survives regeneration.
- [x] `03_story_signature-and-the-doctor-lane` — the frozen sign-off block, and a doctor lane that
      reports at `warn` and gates nothing.

## Dependencies

- **53 (loop-artifact)** — supplies `brief.loop`, the only join between a loop and a run. Without it
  this milestone has a renderer and nothing to render. **53 is `in-progress`**, so sequence this
  behind it rather than beside it.
- **52 (loop-registry-and-graph)** — the loop model, the endpoint grammar and the Mermaid conventions
  this record reuses. Done; pre-authorised an additive face (`ARCHITECTURE.md:869-870`).
- **79 (committed-loop-graph)** — ships the *declared* graph as a committed document, and with it the
  three things this milestone would otherwise have to invent: where a generated document lives, the
  writer's idempotence discipline, and the regenerate-and-diff drift check. 79 has no dependency on
  53 and is buildable now; this milestone scopes its output per item and adds the execution facts and
  the signature.
