# 03 · Archive is a move

## User story

As **an operator whose stream root is 123 done folders around four live ones**,
I want **`aof work archive <NN> | --done` to move an accepted driver's folder, name verbatim, under
`<work.dir>/archive/`**,
so that **the root of `wiki/work` reads as "what is happening"** while every reader that resolves by
ref — `find 52`, `read 52`, `memory ingest`, `depends`, `validate` — still answers for the archived
item, because its number is its identity and its number did not change.

What lands:

- `aof work archive <NN> | --done [--yes] [--json]` in `src/commands/archive.mjs`, registered in the
  command core and reachable as `/aof:archive`. It refuses a driver that is not `done`; a story
  under a live milestone stays put and moves with its milestone later.
- The move rewrites ONLY the relative prose links that cross the archive line (a root-sibling
  `../NN_…` becomes `../archive/NN_…`; a link from inside the archived folder to a root sibling
  gains a `../`) — never a number, never a citation by ref. The one runtime reader of a live item
  path outside `wiki/` (`acd-tune-carries-no-second-rule.test.mjs:21`) is updated to resolve
  through `findWork` so it survives the move.
- The new `dir` is published through the existing publish-on-mutate effect so the fleet cache
  follows; the memory index is regenerated by the existing `memory ingest`, which this story does
  not touch.
- Explicit only — the verify ceremony (`aof:verify`) never archives; `verify.md` gains one line
  pointing at `aof work archive` as the operator's next step, nothing more.
- The command imports no reindex module — FF-12705 is the control that holds it.
