# 119/03 — build brief

Advisory, and the builder's. Not a contract: the task `.feature` scenarios are. Deviating from this
is not a finding.

## The mechanism

The expensive-sounding half is already done for you: the suite walk recurses, the suite predicate and
the configured roots are prefix tests, and the selection path reads them. So an interior costs the
census, the registration control and test selection nothing — which is what makes this a move story
rather than a harness rewrite.

The registry stops naming suites one line at a time and starts spreading one index per directory. The
single decider for *which file contributed which entries* does not change, and that is the whole
safety argument: the controls that guard registration survive precisely because they keep asking the
same component the same question. An index that decided its own membership by reading its directory
would be a second decider, and would quietly break both of them.

The sibling script is a real edit, not an exception. Every one of its suite specifiers names a file
this story moves, so leaving it alone leaves a script that dies at its first import. Re-pointing
specifiers is admitted; making it a second index is not — that distinction is the whole of its rule.

One delivered control pins the exact bytes of two suites this story relocates, and it is reddened
three separate ways: the files move, their relative specifiers re-depth, and one of them holds a flat
directory read plus two literal marker comments the restructure removes. Import lines are demonstrably
not inside a granted region — the control's own self-check proves it by picking one. So the digest
must be re-stamped deliberately, with the reason and the story recorded, rather than nudged until it
passes.

## The verification step

The claim this story lives or dies on is that **the assembled suite set is unchanged**. Prove it two
ways, because either alone is defeatable. Capture the assembled name set at the base commit and
compare it member by member at the tip — no name added, none removed, counts equal, both sides
floored. Then, at the tip, compare the assembled set against the union of names the recursively walked
tree actually exports, in **both** directions, with walk and read floors.

Set equality at HEAD alone cannot see a deletion: if a suite disappears with its entries, both sides
shrink together and the equality still holds. The before/after comparison is what catches that.

One mechanism detail that will cost you an afternoon otherwise — the comparison must **import the
runner first**. Suite-then-runner order dies in a temporal-dead-zone cycle, because one suite imports
the runner back.

## Deliberately out of scope

The oversized suites are not split here; they are downstream of this partition by construction, and
splitting them first would land them back in a flat directory. The ledger entries sitting in this
write set are neither paid nor worsened. And the controls this milestone's earlier stories declared at
flat paths are moved by this story — amend the register once, at the structural review, as a visible
act rather than a mid-build surprise.
